# 综合判断：不增加顶层模块，增加可验证机制

日期：2026-09-24。本文是依据本目录材料形成的本项目建议，不是任何外部论文已经实现的联合系统。正式职责仍见 [architecture](../architecture.md)，接口见 [data-contracts](../data-contracts.md)。

## 统一映射

| 要减少的成本 | 研究线索 | 建议落点 | 不应赋予的权限 |
|---|---|---|---|
| 重复恢复设计语义 | [CAKE](cake.md)、[PyCircuit](pycircuit.md)、[XLS](xls.md) | Design Core 的结构、来源、契约和局部检查 | 不替代独立 golden/物理评估 |
| 从海量产物找相关信息 | [JEV](jev-dataops.md)、[ChipAgents](chipagents.md)、[ChipStack](chipstack.md) | ChipContext 的确定性提取、查询与可选软排序 | 不隐藏强制失败、不决定正确性 |
| 会话与上下文交付 | [DSH](dsh.md) | 薄 runtime 适配 | 不持有领域验收真值 |
| 重复工程执行与资源组织 | [CHIA](chia.md) | 现有工程任务后端 | 不自动保证调用方证据完整性 |
| 工作区复制与回退 | [LayerFS](layerfs.md) | 可替换 WorkspaceBackend | 不作为唯一耐久证据或 OS 安全保证 |
| 试验探索策略 | [Dream-RSI](dream-rsi.md) | SearchTrace/受限 SearchPolicy 的回放 | 不预测未记录后继、不偷看未来 |
| Harness 过拟合与复杂度 | [RRSI](rrsi.md) | 离线提案、审查、评估、剪枝 | 不自行修改评分器和正式实验规则 |
| 弱基线导致虚假优势 | [AgentDSE](agentdse.md) | 专家 Prompt+通用工具强对照 | 不削弱 baseline 工具权限 |

## 两个循环、三类事实

快循环冻结 Harness：准备当前证据 → Agent 分析修改 → 独立评估 → 下一候选。设计语义、运行观测和历史经验分别保存；ContextPacket 只是可重建视图。

慢循环改进环境：多个 Episode → 提出一个机制修改 → 约束检查 → 开发集试验 → 留出和真实评估 → 发布新版本。最终验收合同、golden、原始结果和盲测集不可由改进 Agent 修改。

Dream-RSI 与 RRSI 的组合可降低策略开发成本并约束接受，但必须先验证历史覆盖和状态一致性。更换主模型、上下文策略或 PyCircuit 表示后，需要重新判断记录的后继是否仍有效；回放不能直接测量新生成机制。

## 当前最小工程顺序

1. **可信执行（M0）**：候选和真实 parent、冻结参考、attempt 身份、正确故障分类、进程清理与不可变成本事件。PR #4 是 Legacy 后端，不因引用 CHIA 就自动完成这些保证。
2. **确定性两段式（M1）**：用当前评估产物生成版本化 EvidenceSnapshot，按静态清单准备 ContextPacket，保留 raw drilldown。先在当前 runtime 测量增量，再接 DSH。
3. **小型可选机制试验**：判断模型先 shadow；LayerFS 先兼容性/成本对照；搜索历史先记录，再测试人工回放策略。任何无增益组件都可删除。
4. **PyCircuit 局部资格（M2）**：共同包装边界，不同时改算法，独立 golden 与集成门禁；再接 DesignIndex、来源和反例查询。
5. **泛化与慢循环（M3/M4）**：表示×反馈 2×2、留出模块、自改策略的回放×正则化对照。经验升级为检查/primitive 前复验和审核。

具体责任、依赖与验收仍由 [BACKLOG](../../tracking/BACKLOG.md) 管理；本文没有将任何阶段或 ADR 标为完成。

## 预注册的消融矩阵

| 问题 | 必须固定 | 主要对照 |
|---|---|---|
| 过程知识与检索是否有用 | 同知识内容、模型、工具 | 专家 Prompt 直给 / 按需检索 |
| 两段式是否有效 | 同语言、runtime、知识、门禁 | 原始工具 / 确定性清单 |
| 判断模型是否值得加入 | 同提取器与主 Agent | 规则 / 通用排序器 / JEV 式判断 |
| PyCircuit 的增量是什么 | 同语义、接口、允许延迟、评价条件 | 语言×反馈 2×2；迁移初始差异单列 |
| Workspace 后端是否加速 | 同任务与工具输出要求 | 当前隔离目录 / worktree或reflink / LayerFS |
| 自改策略是否泛化 | 同生成器、历史权限、最终门禁 | 回放筛选×改进约束 2×2，并做真实新搜索 |

主要目标是首个通过最终门禁并达到冻结 QoR 的端到端成本，以及固定预算最佳已验证结果和成功率。统计辅助模型、所有失败尝试、工作区准备、查询、排队、最终验证和人工介入；缺失成本标未知，不补零。并行墙钟不等于各阶段 active time 相加。

对慢循环还要计入环境改进成本。以统一费用单位计算，后续任务累计节省超过开发/评估费用，才达到摊销盈亏点；token、时间和 EDA 小时仍分别报告，不随意相乘为一个神奇分数。

## 相比 Prompt 的可检验价值

Prompt 可以告诉模型关注什么；我们的环境负责真实计算和提供事实、绑定版本、执行检查并保留可审计历史。用户自己写 parser、索引、缓存或查询脚本是合理基线，不是无效对照。

长期差异化应是 PyCircuit 原生语义与来源、可信工程证据、低成本的上下文与实验组织，以及真实任务上的同模型收益，而不是重新实现通用调度、文件系统或多 Agent 框架。上述机制都只是候选，消融无收益时应缩小或移除。
