# Dream-RSI：用历史回放筛选探索策略

核对日期：2026-09-24。阅读范围：**Dream-RSI: Recursive Self-Improvement through Evolving Worlds** 的 arXiv v1 与官方仓库说明。仓库在本次阅读时仍说明完整代码与复现脚本准备发布；未完整复现。

## 原方法的边界

论文主要演化探索策略，而保持 discovery agent、模型、评估器与执行接口固定。策略选择根节点或已观察的分支前沿，组成受限批次或停止；历史树按记录顺序揭示后继。离线阶段不再次生成候选或调用原评估器，也不训练一个预测任意未知结果的世界模型。[S1][S2]

它把“历史供 Agent 阅读”扩展成“历史供策略评估”。旧策略参与候选比较所带来的不退化，仅针对当前固定历史池的回放目标，不能推出未来真实任务单调改善。[S1]

## 与 RRSI 的关系

| 维度 | Dream-RSI | RRSI |
|---|---|---|
| 主要问题 | 完整搜索太贵，策略反馈太慢 | Harness 演化过拟合、噪声与复杂度增长 |
| 主要对象 | 开新方向、继续分支、并行分配、停止 | 更广的提示、工具、控制流、上下文与记忆 |
| 关键反馈 | 历史搜索树回放 | 候选 Harness 在任务上的实际运行结果 |
| 可迁移机制 | 便宜筛选探索策略 | 约束提案、检查泄漏、成本接受与剪枝 |

这不是同一方法的两个版本，也没有在本次材料中找到两者直接比较的实验。结合它们是我们的工程建议：RRSI 式检查 → Dream-RSI 式开发历史回放 → 留出历史 → 新的真实搜索 → 成本/质量接受规则。[RRSI 笔记](rrsi.md)

## 芯片场景最关键的四条限制

**历史覆盖不是反事实完备性。** 只有一条线性轨迹时，无法可靠比较很多未探索分支。未记录后继必须是 unsupported/unknown，不是失败或零分。

**相同源码不是相同生成状态。** 修改 ContextPacket、跨分支历史、模型或语言后，Agent 可能写出完全不同的后继，不能直接把旧候选当成新上下文策略的输出。附录 B.1 要求生成器阅读可用历史，因此改变调度次序的可见上下文影响也需要核对。

**离线策略不能偷看未来。** 回放数据存储与策略可见接口分离，只揭示当时已观察节点；文件名、最佳结果索引和检索都不能泄漏未来。

**节点数不是芯片成本。** 接口失败、综合、P&R、整机回归成本不同；资源竞争改变后，旧耗时只是估计。未进行后布线评估的节点没有最终 PPA，不能以综合指标补成真值。

## 拟接入的最小接口

以下是本项目提案，不是 Dream-RSI 已提供的上游 API：

- `SearchTrace`：真实 parent、design/workspace revision、可见 context 引用、模型/生成设置、评估合同、阶段结果、可见时间与每次 attempt 成本。
- `SearchPolicy`：先只允许 `continue(frontier)`、`open_branch()`、`stop_search(reason)`；Loop Engine 限制资源和合法动作。

停止分成达标交付与未达标终止，不能把 stop 自动算成功。第一版不同时开放改 Prompt、清单、编译器或验收；那些变化需要新的在线数据或独立实验。

## 验证与实施

先修候选谱系、冻结与成本，再实现确定性回放器；用人工轮询、best-first、有限修复策略检验接口。随后才让 Agent 提出小步策略改动，保留 incumbent，回放只决定谁值得花真实 EDA 预算，真实复验决定谁进入正式系统。

消融建议为“有/无回放筛选 × 有/无 RRSI 式改进约束”，所有组仍共享安全边界和最终门禁。按模块家族留出，计入历史采集、策略开发、回放和在线验证成本；不要把 1000 次便宜回放虚构成节省了本来必然发生的 1000 次全流程实验。

## 原文未解决的复现问题

v1 正文的 replay objective 组合最佳分数、尝试成本和并行项；附录 B.2 描述 Pareto AUC 与并行惩罚。本文保留这两个表述，不擅自认定完全等价。公开完整实现后仍需核对真实目标、历史顺序、agent-state 和停止语义。[S1]
