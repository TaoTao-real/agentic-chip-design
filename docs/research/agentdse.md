# AgentDSE：通用推理与仿真反馈应成为强基线

核对日期：2026-09-24。阅读范围：arXiv 摘要与 v1 方法说明；未复现论文实验。

## 原工作支持的内容

历史讨论中未明确题名的 `arXiv:2606.21836`，对应 **AgentDSE: Reasoning-Augmented Architectural Design Space Exploration**。论文研究由通用编码模型与仿真器闭环进行架构设计空间探索，涉及 DNN 映射、软硬件设计和 CPU cache 等场景；其定位不依赖专门微调或预计算设计数据库。[S1][S2]

这些是论文自身的设定与实验场景，不表示它已完成任意 RTL 的周期等价优化，也不表示本项目已经复现其评估次数优势。本文不将摘要中的最大加速作为普遍收益引用。

## 对本项目的启发

AgentDSE 提醒我们：一个能读代码、调用仿真器并利用结果的通用 Agent 已经是有能力的竞争基线。不能用“请优化这个模块”加弱工具作为对照，然后将正常的工程流程收益都归给新表示。

架构参数探索和实现结构优化的合法动作不同，但都适合把设计决策交给 Agent、把评价交给外部工具。我们的领域合同应先明确是在改变架构参数、实现拓扑还是编译映射，再定义正确性和业务目标；不能只使用统一的“更快”分数。

## 与现有架构的映射

它主要对应 Design Agent 与 Evaluation Backend 之间的闭环。我们额外要验证的是：版本化证据、设计来源映射、上下文选择和 PyCircuit 是否在相同主模型与预算下产生增量。它不是新增一个顶层组件的理由。

建议把“通用 Agent + 原始工具 + 专家过程说明”作为正式强基线，允许主动查询和自行编写解析脚本。工具动作合法域、指标定义、初始设计、搜索预算、最终验证保持一致。

## 最小实验

选择一个没有用于框架调参的模块或设计空间，比较原始反馈与确定性 EvidencePacket。记录全部失败、最终达标率、模型/仿真成本及首次最终有效设计时间。只有这一步成立，再评估原生表示或可学习选择器。

仿真分数与真实物理收益属于不同 fidelity；若涉及 IPC、周期数、时钟频率或功耗，应单列其测量来源与组合假设。不能将减少搜索评估次数直接等同于减少总墙钟。
