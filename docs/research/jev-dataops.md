# JEV DataOps：将低成本判断与复杂生成分开

核对日期：2026-09-24。阅读范围：项目 README、领域接入说明及 TypeSafe confidence 文档；没有调用 JEV、训练目标模型或运行领域 benchmark。

## 原工作实际做什么

JEV DataOps 对 JSONL/CSV 中的文本、指令或对话记录进行格式/重复筛查和模型判断，划分 `keep / review / reject`，再让另一个目标模型训练与评估。它不是逐 token 的训练收益预测器。项目演示模式使用本地规则和 byte-bigram，不代表真实调用 JEV 或训练了 LLM。[S1]

领域指南要求定义自己的 rubric 与任务评估；代码或金融类 rubric 不会自动执行程序或证明外部事实。TypeSafe 的 confidence 是基于输出分布的统计量，需要按领域校准，不可直接等同芯片判断的正确率。[S2][S3]

## 对本项目的迁移建议

借鉴“判断与生成解耦”，不搬入训练流水线：

```text
确定性提取/身份校验/设计关联
    → 可选的类型化相关性判断
    → 主 Design Agent 的诊断和修改
    → 独立工具与控制器验收
```

未计划专项训练芯片模型，不意味着所有子任务必须使用同一个大模型。可使用现成排序器或判断服务，但要允许替换并单独计费；规则已足够时，多一次模型调用可能更慢。

判断对象应是 Evidence Bundle，而不是任意 token。路径、延迟、阶段、候选、约束和相关设计必须成组保留。当前候选归属、数值单位、可比性、失败状态由程序检查；模型只辅助选择“先看什么”或“还缺什么”。

## 必需、优先、按需与待确认

| 交付状态 | 用法 |
|---|---|
| 必需 | 合同、当前失败、版本不符、关键缺失，无条件提供 |
| 优先 | 当前相关路径、变更子图、适用历史，在预算内排序 |
| 按需 | 完整原始报告和较远历史，保留可寻址引用 |
| 待确认 | 冲突、低置信映射、陌生日志，允许升级调查 |

不进入首屏不等于删除；模型不得隐藏反例、不利结果或验证失败。不要将“文本优质”当成“当前设计决策有用”。外发模型前先执行真实的数据权限策略，不能让外部模型看过敏感数据后才判断是否该发送。

## 最小消融

固定主 Agent、设计、知识、工具和预算，比较原始工具、确定性清单、通用排序器、JEV 式判断四种条件。先 shadow mode 只记录判断，不改变输入；核验关键证据遗漏，再开放选择并保留回退。

计入辅助模型全部 token/延迟/费用，测补充查询、错误候选、昂贵 EDA 次数及最终交付成本。少输入但多试错不是成功。成功轨迹里“引用了某条证据”只提供关联，是否有效仍需字段/选择器消融。
