# 团队对齐：研究对象、责任和验收

状态：架构提案；负责人、预算和验收阈值待团队确认。依据项目讨论与对齐稿整理，不是批准记录。

## 一句话

把 Agent 每轮重新恢复的芯片工程事实转成可追溯的计算结果，让同一个模型更省总成本地完成真实设计优化。

## 范围

不以专项后训练为当前核心，不重新建设仿真/EDA 求解器；会建设适配、索引、检查和数据准备能力。未来以 PyCircuit 为原生设计核心，近期兼容 Chisel/RTL。BOOM 用来验证方法，长期目标是 AI workload、编译器和硬件资源的协同设计。

## 四个领域模块

| 模块 | 负责 | 不负责 |
|---|---|---|
| Design Core | 可编辑设计及派生 IR/RTL、结构索引、检查入口 | 不将当前 slack 当作设计语义 |
| ChipContext | 解析、校验、关联、比较、选择、按需下钻 | 不把猜测当测量，不验收候选 |
| Loop Engine | 合同、权限、候选、预算、工具调度、最终验收 | 不允许 Agent 修改测试或评分器 |
| KnowledgeStore | 观察、假设、实验、经验和适用范围 | 不把目标历史泄漏给盲测 |

DSH 是拟选 runtime；现有 CHIA/Ray/脚本负责工程任务执行。两者可并存，领域数据不依赖其内部对象。现有 BOOM 记录不能表述为 DSH 已产生效果。

## 本轮希望确认

1. 冻结同模型环境效率的命题，以及专家 Prompt + 脚本强基线。
2. 批准 M0/M1 和一个 M2 局部等价资格实验；不同时启动整核迁移、多 Agent 扩容和自动编译器自修改。
3. 由验证负责人维护合同、成本、留出任务和最终门禁；由架构负责人维护领域数据契约。
4. 没有可重复收益时允许删除或收缩组件，不以组件数量作为进展。

## 当前证据

已有工程闭环和通用过程知识的单次配对信号；未证明端到端整体加速，也未单独验证结构化当前反馈、DSH 或 PyCircuit。公开摘要见 [BOOM v2](../experiments/boom-v2/README.md)。

## 成功定义

相同最终 QoR、正确性与成功率要求下，减少从共同起点到最终有效候选的墙钟或明确的工程成本。计入准备、模型、构建、EDA、排队、最终验证和人工；不使用任意乘积分数掩盖权衡。

三条建议工作线为 Agent/上下文、PyCircuit/编译器、验证/实验。它们是责任划分，不预设新增人员数量。
