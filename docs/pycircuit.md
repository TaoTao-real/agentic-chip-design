# PyCircuit：未来设计核心与近期接入

状态：本项目改造路线提案。具体上游能力和 commit 需核验；不能把本页目标接口当作已实现。

## 核心定位

PyCircuit 同时是可编辑设计表示和编译器可计算的设计事实生产者。DSH 是交付接口；ChipContext 关联测量；控制器最终验收。差异化不在 Python 语法，也不在往 IR 添加更多描述性注释。

## 第一批能力

| 能力 | 拟产物 | 评价 |
|---|---|---|
| 来源关联 | Python–IR–RTL 的版本化 origin 与实体索引 | 覆盖率、错定位率、定位成本 |
| 依赖/影响查询 | fanin、fanout、状态边界、修改影响子图 | 与完整设计交叉检查、减少重复读取 |
| 契约与诊断 | 接口、类型、周期约束及错误位置 | 明确静态可检查项与必须独立验证项 |
| 局部验证 | 可执行子块、独立参考、反例重放 | 失败候选成本及集成验证通过率 |

索引从源码/IR 派生，不是另一份可手改的硬件。生成名称不是跨版本永久身份。物理映射允许多对多和未知，不假设综合后仍一一对应。

## 渐进接入

1. 保留原 BOOM、工具和 runtime，选边界明确的组合子块。
2. 先固定共同包装边界，单独测重构影响。
3. PyCircuit 移植忠实保留原始行为和初始算法，不顺便植入已知优化答案。
4. 原始 Chisel 生成 RTL 作为独立 golden；新的 C++/RTL 后端相互一致仍不能替代独立参考。
5. 局部验证通过后嵌回原 BOOM，执行相同整模块与整机最终门禁。
6. 接入 DesignIndex，再开放 Agent 修改并做消融。

对精确周期行为任务先使用显式硬件构造路径；不能仅因名字是 IssueQueue 就假设 ACIR 的事务级 Queue 等价于原始实现。ACIR 资源/队列建模留给后续架构探索。

## 非目标

不整体重写 BOOM；不在规范 IR 中累积所有测量；不把局部等价或快速结构指标等同整模块后布线结论；不默认保留综合对象牺牲优化来换取漂亮映射。

## 机制对照

先报告包装和未优化语言迁移本身的 PPA/成本，再比较同模型在 Chisel/PyCircuit × raw/aligned feedback 四组中的增量。契约、golden 和权限一致。初始 QoR 不同则同时报告绝对目标和相对改善。

## 与 Prompt 的差异

Prompt 可以要求定位和验证，设计核心实际产生关系、约束与可运行验证对象。Chisel/RTL 加脚本也可实现类似能力；我们要证明原生生产的信息更准确、低成本、易维护，而不是宣称不可复制。

远期再将跨任务验证的经验提升为通用语义操作、诊断与策略，逐步扩展 workload→compiler op→hardware resource 映射。
