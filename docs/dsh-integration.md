# DSH 薄适配：实施提案

**尚未实现或通过本项目 smoke test。** 上游版本、插件接口和生命周期在 ACD-008 核验锁定；旧聊天示意代码不能直接当成可运行实现。

## 定位

现有 Python 领域服务、候选控制器和 EDA 入口继续保留。DSH 承载模型会话、工具协议与上下文交付；不拥有设计语义、测量真值或验收权。

## 事件映射

| 时机 | 工作 |
|---|---|
| 插件装载 | 注册服务、工具、配置和监听器 |
| 评估完成 | 我们的 Loop Engine 发出封存事件，准备服务解析产物；不是默认 DSH 硬件事件 |
| 模型调用前 | 读取已经就绪的数据，检查版本和预算，交付有来源的 packet |
| 消息持久化后 | 更新已交付状态，避免取消时丢失更新 |
| 会话压缩/恢复 | 从持久状态重建必要 snapshot |

不能仅在 turn 的第一步注入；评估可能在后续工具步骤完成。按证据变化而非每次 step 无条件注入。不得使用全局 latest_report 混淆候选和分支。

## 领域接口

输入：experiment、candidate、design revision、知识权限、session/branch/context generation。
输出：ContextPacket 和有界证据/设计/反例查询。

示例策略文件见 [配置](../configs/evidence-policy.example.json)，它是我们的领域提案，不是上游原生配置。

## token 与缓存

去重并不意味着历史消息不重发、不占窗口或不计费。静态规则与动态证据分开，短期 snapshot + delta，压缩边界重建状态。分别记录缓存读、未缓存输入、输出、费用和压缩成本。

## 接入与对照

先在当前 runtime 跑通相同领域服务，再做 DSH 薄适配。换 runtime 不与换语言、反馈和模型一起成为主对照变量。完成条件包括真实版本记录、注册/注入 smoke test、并行/取消/恢复测试和可见上下文审计。
