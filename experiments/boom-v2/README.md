# BOOM v2：阶段判断公开摘要

可公开的 CHIA/Ray 执行代码、便携配置与部署说明见
[`harness/`](harness/README.md)。该目录不包含候选补丁、目标专用知识、
完整模型会话或 EDA 原始产物。

状态：来自项目方提供的实验记录与此前评审的聚合摘要。本次上传没有重新运行 EDA。原始报告、JSON、完整会话、主机身份、完整环境快照和候选实现不在公开仓库；本页不构成可独立复现认证。

## 分组

K0 无历史知识，仍可自主读取源码/RTL/时序并评估，不应叫没有反馈的盲目修改。

K1 增加通用过程知识，主要涉及验证纪律、证据使用和失败恢复，不提供当前目标历史解法。

K2 允许同目标历史知识，衡量复用，不能用于证明从零发现。访问权限和实际读到的知识需要分别审计；未检查全会话前不把 K2 对 K1 当成完美单因素增量。

## 固定 24 回合

| 指标 | K0 | K1 | K2 |
|---|---:|---:|---:|
| 候选早期评估次数 | 2 | 2 | 5 |
| Provider 总 token | 1,394,180 | 934,649 | 1,163,464 |
| 搜索墙钟（秒） | 1,227 | 1,308 | 2,193 |
| 后布线延迟（ns） | 21.999 | 21.262 | 22.055 |
| LUT | 49,723 | 50,232 | 50,096 |

早期评估次数不是 P&R 次数。Provider 总 token 包含缓存命中，不能直接代表实际费用。

K1 总 token 比 K0 少 32.96%，搜索墙钟多 6.60%。因此只能说出现 token 节约信号，不能说固定预算整体更快。

## 事后搜索门槛重放

按“功能/面积门禁通过，且后综合延迟改善至少 20%”重放：

| 指标 | K0 | K1 | K2 |
|---|---:|---:|---:|
| 首次搜索有效回合 | 18 | 16 | 9 |
| 累计 token | 745,483 | 396,345 | 155,231 |
| 累计搜索时间（秒） | 1,102 | 610 | 686 |
| 当时后综合延迟（ns） | 22.295 | 23.177 | 23.420 |

K1 对 K0 的 token/时间分别少 46.83%/44.65%。这是事后阈值重放，不是正式执行的早停交付实验；不能省略 finalization 成本。K2 首个搜索达标候选没有单独完成最终评估，不能把它当最终有效结果。

## 对架构的启示

- 过程知识可能改善前半程搜索，但当前未单独验证自动运行反馈清洗、DSH 或 PyCircuit。
- 后综合 K0 优于 K1，后布线排序相反，说明不能把快指标当唯一最终裁判。
- 仍需调查跨源码/RTL/时序定位的成本；工具调用次数不是全部冗余的证明。
- 正式早停和预算探索是不同任务，应各自冻结协议。

## 边界与下一步

这是单次同 seed 的 POC，不是多个独立 Agent 搜索。随机差分种子重复不能替代搜索重复；共享计算资源也会影响墙钟。

三组最终通过状态是原报告中的验证结论。结果仅指定 FPGA 模块级面积与时序，不外推 ASIC、整机 IPC、功耗或已达成时钟约束。

下一轮：同内容专家 Prompt 对照；成对独立搜索；冻结最终验收与停止策略；审计实际可见知识；留出模块迁移；两段式反馈与 PyCircuit 分别消融。见 [评估协议](../../docs/evaluation.md)。
